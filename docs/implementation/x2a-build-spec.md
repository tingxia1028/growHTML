## RESUME NOTE (2026-07-05, from a directTransport import-graph trace before the track was paused)
**Delta 1 is DEEPER than "make AI routes lazy."** Root cause of the ai-barrel leak: `src/server/services/errors.ts:8` imports `VisionUnsupportedError` from the `src/ai` barrel AT MODULE SCOPE. Since ~every service imports `errors.ts`, that statically pulls `src/ai/index.ts` → `claudeCliProvider.ts:1-2` (`node:child_process`, `node:crypto`) into **8 of 12** directTransport services (anchors/graph/layers/notes/patches/sourceFork/sources/search). So the node-free mobile graph requires FIRST relocating `VisionUnsupportedError` (and any other ai-barrel error types) OUT of the barrel into a pure module `errors.ts` can import without evaluating providers. Additional direct node leaks confirmed: `sourceAuthoring.ts:12-13` (node:fs/path) + its `svpack.ts` import (delta 5 — exclude share-status); pure `node:path`-only (acceptable, needs a posix shim / stub): memory.ts:21, reviewSchedule.ts:17, triggerFires.ts:19. Net: X2-A commit 1 should be "extract ai error types to a pure module + repoint errors.ts" BEFORE the CapacitorStorage adapter, or the import-check (delta 6) can't go green.
